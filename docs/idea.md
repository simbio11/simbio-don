## 2. 돈 아끼는 게임 (소비 시뮬 + 저금통)

📄 **상세 기획안: [[WEB-6_don — 기획안]]** (v0.2 — Android 네이티브 · Google Play · 예산 엔진 · 알림 파싱 · 아이템 창고 · 마일스톤 M0~M4) · **2026-10-07 WEB-6으로 승격**

**원안** — 쇼핑·배달 같은 휴대폰 결제를 **모의로** 하게 한다. 토스를 연결해 무언가를 "사면" 실제로 구매되지 않고 **본인 저금통에 들어가게** 해서, 소비 욕구는 풀리고 돈은 모인다.

**핵심 루프** — 상품 탐색 → 장바구니 → 결제(모의) → **저금통 적립** + 소비 기록 → 주간 리포트("안 쓴 돈 = 모은 돈")

**설계 요소** — 가상 카탈로그(실제 상품·가격), 모의 결제 화면, 저금통 대시보드·목표 금액, 충동구매 지연 타이머(결제 전 대기), 절약 리워드

### 🔴 실존 확인 ① — 결제(토스) 전제

- **개인의 결제를 가로채 저금통으로 돌리는 토스 공개 API는 없습니다.** 토스페이먼츠는 **PG 가맹점 계약(= 사업자등록 전제)** 기반 결제 수납 API이고, 계약 전에도 테스트 키로 결제 흐름만 미리 구현할 수 있습니다(출처: 토스페이먼츠 개발자센터 문서 · 제이씨랩 연동 가이드, 2026-10-07 확인).
- 따라서 **1차 구현은 모의 결제(가상 체크아웃)**로 하고, 게임 본체는 실제 결제·계좌 연동 없이도 성립합니다.
- 실제 결제·계좌 자동화는 금융 규제·약관 리스크가 있어 모의로 두는 편이 안전합니다.

### 🔴 실존 확인 ② — "버튼 누르면 실제 저금통 계좌로 돈이 나가게" (2026-10-07 조사)

**결론: 개인 자격으로는 완전 자동이 불가능합니다. 우회 경로는 4가지가 있습니다.**

근거 (전부 1차 문서 확인):
- **오픈뱅킹 '이용기관'은 기업만** — "금융결제원과 오픈뱅킹 이용계약을 체결하고 이용승인을 받은 **핀테크사업자 및 참가기관**"이며 이용 대상은 핀테크산업 분류업종 기업·전자금융업자·전자금융보조업자입니다. 개인(비사업자)은 대상이 아닙니다(출처: 금융결제원 통합포털 오픈뱅킹 참가기관 페이지).
- **개인회원은 테스트만 가능** — 은행 오픈API 포털 기준 "개인회원은 앱 생성·테스트베드 테스트만 가능"이고, **운영전환(실서비스)·정보보호 보안심사는 기업회원(마스터)만** 신청할 수 있습니다(출처: IBK 오픈API 포털 이용안내).
- **출금이체의 목적지가 '이용기관 계좌'** — 출금이체는 "이용기관이 사용자 계좌에서 출금하여 **이용기관의 수납 모계좌로 집금**하는 업무"입니다(출처: 오픈뱅킹공동업무 출금이체·자동계좌이체 약관). 즉 구조상 돈이 비오님 저금통 계좌로 직접 가지 않습니다. 사용자 측에는 전자금융거래법 §15① 및 시행령 §10에 따른 **계좌 단위 사전동의**(서면·전자서명·ARS)가 필요합니다.
- **게임이 돈을 받아 보관·환급하는 구조는 별도 규제** — 선불전자지급수단 등록 대상이 되면 선불충전금 별도관리 등 의무가 붙고, 미등록 시 **3년 이하 징역·2천만원 이하 벌금**(2024-09-15 개정 전자금융거래법, 출처: 금융위 보도자료 · 법무법인 세움 해설). 개인용 도구로는 감수할 대상이 아닙니다 — ⚠️ 법률 판단은 전문가 확인 필요, 여기서는 위험 존재만 기록.

| :--- | :--- | :--- | :--- | :--- |

- ⚠️ **"얼마나 모였는지"를 게임이 아는 것도 별개 문제** — 계좌 잔액·거래내역 조회 역시 오픈뱅킹 이용기관 자격이 필요합니다. 현실적 해법은 **최초 1회 현재 저금통 잔액을 사람이 입력**하고 이후는 게임이 누적 계산하는 것입니다(구 D-8 가계부가 "은행 알림 미설정 → 수거 0건"으로 접힌 지점과 동일 — [[05_실험과_보류]]).
- **아린 권고(안)** (보류 — 아래 채택안으로 대체됨): A + C 조합.

### ✅ 채택안 (2026-10-07 비오님 결정) — 순수 모의 + 대리만족

**결정: 실제 돈과 연결하지 않습니다.** 게임이 자체 재화를 지급 → 그 돈으로 마음껏 소비(쇼핑·배달 모의) → **구매한 아이템이 창고에 쌓임** → 대리만족. 여기에 **주간 절약 리포트**를 얹습니다.

- **장점** — 법적·규제 이슈 0, 계좌·API 연동 0, 실패 지점 0(WEB-5 게임 제작 경험 그대로 재사용). 위 A~D 표는 실제 이체가 필요해질 때만 참고하고, 기본 설계에서는 **사용하지 않습니다**.
- **설계 쟁점 1개 — "많이 쓰기(대리만족)"와 "안 쓰기(절약)"는 같은 재화를 쓰면 서로 싸웁니다.** 둘 중 하나로 정해야 합니다.
  - **① 분리형(권고)**: 게임 화폐는 무한·리셋되며 재미로만 소비 → 창고 채우기 / 절약은 **별도 화면에서 "오늘 참은 금액"을 직접 입력·선택** → 주간 리포트. 두 동기가 충돌하지 않습니다.
  - **② 예산형**: 게임이 주간 예산을 지급하고 **남은 금액이 곧 절약액**. 적게 쓰면 절약, 많이 쓰면 대리만족 — 트레이드오프 자체가 재미 요소가 되지만, "많이 쓰고 싶은데 아껴야 한다"는 죄책감이 붙을 수 있습니다.
- **창고(인벤토리)가 대리만족의 핵심** — 아이템 수집·전시·등급이 재미의 몸통입니다. **WEB-5 도트 가문 키우기**의 카드 구조(직업 232종·카드 282장·숨겨진 해금)를 그대로 참고할 수 있고, 아이템 이미지는 기존 이미지 생성 파이프라인(제미나이 · 아비스)으로 조달합니다.
- **주간 절약 리포트** — "이번 주 12,000원 아꼈어요" 형태. 입력 방식(직접 입력 vs 게임 화폐 잔액 자동 계산)은 위 ①/② 선택에 따라 결정됩니다.
- **실제 저축과 연결하고 싶어지면** — 그때 위 A안(은행 앱 자동 모으기에 위임)을 **별도 기능으로 분리**해 얹습니다. 게임 본체는 실제 돈을 몰라도 됩니다.

### ✅ 채택안 v2 (2026-10-07 비오님 추가 결정) — 예산형 + 실제 지출 자동 기록

**확정**: 위 ② **예산형**. **실제 월급을 입력하면 그에 맞춰 주 단위 예산을 짜주는** 구조로 갑니다. 여기에 **재화를 불리는 시스템**을 얹고, 가능하면 **폰 결제 알림을 자동으로 읽어 실제 지출을 반영**합니다.

- **기본 흐름** — 월급 입력(로컬 저장 · 외부 전송 없음) → 고정비 차감 → **주 단위 예산 배분** → 게임 재화 = 예산 → 소비(모의 또는 실제) → 남은 잔액이 저금통 + **아이템 창고 적립(대리만족)** → 주간 리포트
- **재화 불리기 시스템** — 이자·소액 투자·미니게임 보상 등으로 예산을 굴립니다. ⚠️ 너무 잘 불리면 "절약"의 의미가 희석되고 예산 게임 자체가 무너집니다 → **보너스 상한(주 예산의 5~10% 수준)**과 예치·잠금 개념을 권합니다.
- **🔴 알림 자동 기입 조사 결과 (2026-10-07)**
  - **안드로이드는 실제로 가능합니다.** 카드사·은행·간편결제 앱의 결제 알림을 자동 인식해 지출·수입을 기록하는 가계부 앱이 실존합니다(예: 스마트가계부 · 편한가계부 문자 자동인식 · 비주얼 가계부 — "은행/카드 앱 알림은 연동 이후 내역만 기록"). 기술 근거는 Android `NotificationListenerService`(사용자가 설정에서 알림 접근 권한 허용).
  - **iPhone은 불가** — iOS 정책상 문자·앱 알림 자동 인식이 막혀 있고, 단축어 자동화로 반쪽만 됩니다(편한가계부 iOS 안내 · 사용자 커뮤니티 다수 확인).
  - **앱인토스(토스 미니앱)로는 불가** — "네이티브 라이브러리는 사용하실 수 없습니다"(토스 테크챗 SDK 답변). 웹 번들로 도는 구조라 안드로이드 알림 접근 권한을 쓸 수 없습니다 → 알림 수집을 하려면 **네이티브 안드로이드 앱**이어야 합니다.
  - **마이데이터는 개인 불가** — 신용정보원·금융결제원 중계 API는 허가받은 사업자(뱅크샐러드 등)용입니다. 개인은 **알림 파싱이 현실 경로**입니다.
  - ⚠️ **구 D-8 가계부가 접힌 지점이 바로 여기** — 실패 원인은 기술이 아니라 **알림 미설정**이었습니다([[05_실험과_보류]]). 이번엔 카드·은행·간편결제 앱의 결제 알림을 켜두는 준비(사람 손 1회)가 선행 조건입니다.
  - 🔒 **보안** — 알림 접근 권한은 모든 알림(문자·인증번호 포함)을 볼 수 있는 권한입니다 → **결제 알림만 파싱 · 외부 서버 전송 없음(로컬 처리)**, 코드는 비오님이 검토할 수 있게 두는 조건으로 설계합니다.
- **결정 필요 2건** — ① 폰 OS(안드로이드여야 자동 기입 가능. 갤럭시워치 사용 이력으로 보아 갤럭시일 가능성이 높으나 **확인 필요**) ② 형태(네이티브 안드로이드 앱 vs 앱인토스 미니앱 — 후자는 알림 자동기입을 포기하고 수동 입력만)
- 💡 개인용 Android 앱을 APK로 직접 설치하면 **스토어 심사·게임 등급분류를 피할 수 있습니다**(배포하지 않는 전제). 배포로 갈 때만 등급이 필요합니다.

**볼트 자산 연결** — 토스 앱 생태계 경험은 이미 있습니다: [[WEB-5_가문 키우기 — 앱인토스 등록 시트]] (SDK 3.7.0 · 토스앱 WebView CORS · 게임 등급분류 절차). 앱인토스 경로로 가면 그대로 재사용합니다.

**착수 시 결정 필요** — ① 저금통을 가상으로만 둘지, 실계좌 연동을 목표로 할지(비오님 판단) ② 쇼핑 데이터를 어디까지 실제로 쓸지(웹 자동화 금지 — API만)
